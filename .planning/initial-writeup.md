The indexers are becoming complex as we add more indexers/chains. Our RPC is currently tangled in as a singular RPC task that should be moved to the indexer side too for that respective chain. The rpc part can be done later, but we need to add abstractions over the indexer now so we don't kill ourselves adding more integrations as we go on.

Current flow for indexers is starting at Cli::Start where each indexer is spunned up as a separate task. RPC on the other hand is a singular task for all indexers, but it already makes use of an enum over clients. We should eventually make these clients the one and the same with the indexers alongside the common interface.

I think we should go about this is defining a common client interface that would allow us to just write the concrete client for each chain/indexer/rpc directly. Then interface with it through a common interface. Design this for me, but do not implement yet. Go against me if this is not the best approach once you've seen more of the codebase and are confident about the design. We want the simplest approach possible as to not add more complexity down the line. We already know we'll need an additional integration than what we already (hydration, ethereum, solana). Note that NEAR (aka indexer.rs) is not necessary to simplify along with this since that is more for testing purposes. Ask me questions where things are not clear
